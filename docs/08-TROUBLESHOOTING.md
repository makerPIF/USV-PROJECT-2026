## A. 전원이 안 들어온다

### A-1. 아무것도 안 켜진다

| 확인 | 방법 | 정상값 |
|---|---|---|
| 배터리 전압 | 멀티미터로 배터리 단자 | 11.1~12.6 V |
| 메인 스위치 | 스위치 양단 저항 | ON에서 0 Ω에 가깝게 |
| 퓨즈 | 퓨즈 양단 저항 | 0 Ω에 가깝게 (끊기면 ∞) |
| UBEC 출력 | UBEC 출력선 전압 | 5.0~5.3 V |

퓨즈가 끊겼다면 **원인을 찾기 전에 갈아 끼우지 마세요.** 퓨즈는 어딘가 단락됐다는 신호입니다.
배터리를 뺀 상태에서 메인 +와 − 사이 저항을 재 보세요. 수 Ω 이하면 단락입니다.

### A-2. ESP32만 안 켜진다

- USB로는 켜지는데 배터리로는 안 켜진다 → UBEC #1의 5V가 ESP32의 **5V 핀**(VIN 아님)에 들어가는지 확인
- 둘 다 안 켜진다 → ESP32 모듈 자체 불량일 수 있습니다. 다른 보드로 교체해 보세요

### A-3. 켰다가 바로 꺼진다 (브라운아웃)

모터를 돌리는 순간 ESP32가 재부팅된다면 **전압 강하**입니다.

1. 배터리와 ESC 사이 배선이 너무 가늘지 않은지 (최소 14 AWG)
2. UBEC가 모터와 **같은 배터리에서 따로 분기**되어 있는지 — ESC 뒤에서 뽑으면 안 됩니다
3. ESC와 배터리 사이에 **470 µF 이상 전해 커패시터**를 추가
4. 커넥터 접점 저항 — XT60을 꽉 눌러 끼웠는지

## B. Wi-Fi·GCS 연결이 안 된다

### B-1. `대전중앙중학교` SSID가 안 보인다

1. 공유기 LED가 켜져 있는지 → 안 켜지면 UBEC #2 출력 확인(5 V)
2. 공유기 설정이 날아갔는지 → 초기화 후 [05-NETWORK.md 1장](05-NETWORK.md#1-공유기-설정) 다시
3. **2.4 GHz가 꺼져 있지 않은지** — 5GHz만 살아 있으면 ESP32는 접속할 수 없습니다
4. 노트북이 5 GHz 전용 모드가 아닌지

### B-2. SSID는 보이는데 GCS가 연결되지 않는다

연결 순서대로 하나씩 확인하세요.

```
노트북 ──① Wi-Fi 접속──► 공유기 ──② ESP32 접속──► ESP32 ──③ WebSocket──► GCS
```

**① 노트북이 공유기에 붙었는지**
```
ping 192.168.8.1
```
응답이 없으면 공유기 Wi-Fi에 접속되지 않은 것입니다. 노트북이 휴대폰 핫스팟에 붙어 있는 경우가 흔합니다.

**② ESP32가 공유기에 붙었는지**
```
ping 192.168.8.20
```
응답이 없으면 ESP32가 Wi-Fi에 못 붙은 것입니다. USB로 연결해 시리얼 모니터(115200)를 열면
접속 로그가 보입니다. 비밀번호 `2026USV` 를 확인하세요 — 대소문자를 구분합니다.

**③ ping은 되는데 GCS가 연결되지 않는다**
- GCS 주소칸이 `192.168.8.20` 인지 (`http://` 를 붙이면 안 됩니다)
- 브라우저를 새로 고침(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>)
- <kbd>F12</kbd> → Console 에 WebSocket 오류가 있는지

### B-3. 연결은 되는데 자꾸 끊긴다

| 원인 | 확인 | 대처 |
|---|---|---|
| 신호 약함 | RSSI가 −75 dBm 아래 | 거리를 줄이거나 안테나 개선 |
| 채널 간섭 | Wi-Fi 분석 앱으로 혼잡도 | 채널을 1·6·11 중 한산한 쪽으로 |
| 영상이 대역폭 독점 | 영상 끄면 안정적 | 해상도를 QVGA로 |
| 공유기 과열 | 만져서 뜨거운지 | 환기구 확보, 직사광 차단 |
| 전원 불안정 | 모터 돌릴 때만 끊김 | A-3 참고 |

### B-4. 다른 노트북에서는 되는데 내 노트북에서만 안 된다

- 회사·학교 보안 프로그램이 로컬 네트워크를 막는 경우가 있습니다
- VPN이 켜져 있으면 끄세요
- 방화벽에서 브라우저의 로컬 네트워크 접근을 허용하세요

## C. 모터가 안 돈다 / 이상하게 돈다

> [!CAUTION]
> **이 절의 모든 시험은 프로펠러를 빼고 하세요.** 예외 없습니다.

### C-1. 시동(ARM)이 안 걸린다

GCS 로그에 뜬 사유를 보세요. 사유 없이 안 걸리면 아래를 차례로.

| 조건 | 확인 |
|---|---|
| 배터리 10.2 V 이상 | 상태 타일의 전압 |
| 롤 70° 이내 | 자세 타일 — 배가 기울어진 채 놓여 있지 않은지 |
| 스로틀 중립 | 키보드에서 손 떼고 다시 |
| RC 모드가 아닌지 | `조종권` 타일이 `GCS` 인지 |
| RC 모드라면 CH6 | 조종기 스위치가 ARM 위치인지 |

### C-2. 시동은 걸리는데 모터가 전혀 안 돈다

1. **ESC 비프음을 들으세요.** 전원을 넣었을 때 "삐-삐-삐" 하는 시동음이 나는지
   - 소리가 없다 → ESC에 전원이 안 들어옵니다. 배터리·퓨즈 확인
   - 소리는 나는데 안 돈다 → 신호선 문제. 다음으로
2. **신호선 확인** — ESC 신호선(흰색/노란색)이 GPIO25·26에 들어갔는지,
   **접지선(갈색/검정)이 ESP32 GND와 연결됐는지**. 접지 공통이 빠지면 신호가 전달되지 않습니다
3. **ESC와 모터 3선** — 세 선 중 하나라도 빠지면 돌지 않습니다. 바나나 커넥터를 다시 꽂아 보세요
4. GCS의 `ESC 펄스` 값이 1500에서 변하는지 확인 → 변하는데 안 돌면 ESC/모터 쪽,
   안 변하면 펌웨어/명령 쪽

### C-3. 전진만 되고 후진이 안 된다 ⭐ 가장 흔한 문제

**ESC가 Bidirectional(3D) 모드로 설정되지 않은 것입니다.**

기본 설정 ESC는 1000~2000 µs를 "정지~전속"으로 해석합니다. 이 상태로는 아무리 명령을 보내도
역회전하지 않습니다. BLHeli_S 설정 프로그램으로 다음을 바꾸세요.

```
Motor Direction : Bidirectional        ← 이것이 핵심
Brake On Stop   : Off
Low RPM Power Protect : Off
```

자세한 절차는 [01-HARDWARE.md 의 ESC를 후진 가능하게 만들기](01-HARDWARE.md#7-esc를-후진-가능하게-만들기)에 있습니다.
설정 후에는 **1500 µs에서 정지**하는지 반드시 확인하세요.

### C-4. 한쪽 모터만 돈다

1. 좌우 ESC 신호선을 **서로 바꿔** 꽂아 보세요
   - 안 돌던 쪽이 돌면 → ESP32의 해당 GPIO 또는 펌웨어 문제
   - 그대로 안 돌면 → 그 ESC 또는 모터 문제
2. 모터를 손으로 돌려 보세요. 걸리는 느낌이 있으면 베어링 손상이나 수초 감김

### C-5. 방향이 반대다

| 증상 | 대처 |
|---|---|
| 둘 다 전후진이 뒤바뀜 | 양쪽 모터의 3선 중 **아무 두 개**를 서로 바꿔 끼움 |
| 한쪽만 반대 | 그쪽 모터의 3선 중 두 개를 바꿔 끼움 |
| 좌우 조향이 반대 | 좌우 ESC 신호선을 서로 바꿔 꽂음 |

> 펌웨어를 고치는 것보다 선을 바꾸는 쪽이 빠르고 확실합니다.

### C-6. 떨리거나 "삑삑" 소리만 난다

- **동기 이탈(desync)** — 프로펠러가 너무 큽니다. 한 치수 작은 것으로
- 모터 3선 중 하나가 접촉 불량
- ESC 타이밍 설정이 모터와 맞지 않음 → BLHeli_S에서 Timing을 `Medium` 으로
- 저전압 — 배터리 잔량 확인

### C-7. 모터가 뜨겁다

손을 1초 이상 못 댈 정도면(약 70 °C 이상) 즉시 멈추세요.

| 원인 | 대처 |
|---|---|
| 프로펠러가 너무 큼 | 한 치수 작게 — 가장 흔한 원인 |
| 수초·낚싯줄 감김 | 프로펠러·샤프트 청소 |
| 구동축 정렬 불량 | 커플러·스터핑 박스 정렬 재확인 ([04-ASSEMBLY.md](04-ASSEMBLY.md)) |
| 베어링 마모 | 모터 교체 |
| 장시간 고출력 | 출력 제한을 낮추고 간헐 운전 |

**A2212 1000KV 기준 적정 프로펠러**는 [02-ORDERING.md 의 프로펠러 크기 맞추기](02-ORDERING.md#3-프로펠러-크기-맞추기)을 보세요.
무부하 공회전에서 1분, 물에서 2분 돌려 보고 온도로 판단하는 절차가 적혀 있습니다.

## D. 센서값이 이상하다

### D-1. 자세값이 전부 0이거나 안 변한다

MPU6050과 통신이 안 되는 것입니다.

1. **배선** — SDA→GPIO21, SCL→GPIO22, VCC→3.3V, GND→GND
   (5 V를 넣어도 대부분 동작하지만 3.3 V를 권장합니다)
2. **I²C 주소** — AD0 핀을 GND에 두면 `0x68`, 3.3V에 두면 `0x69`.
   펌웨어는 `0x68` 기준입니다
3. **I²C 스캐너**로 확인 — 아래 스케치를 올려 시리얼 모니터를 보세요
   ```cpp
   #include <Wire.h>
   void setup(){ Serial.begin(115200); Wire.begin(21,22);
     for(uint8_t a=1;a<127;a++){ Wire.beginTransmission(a);
       if(Wire.endTransmission()==0){ Serial.printf("발견: 0x%02X\n",a); } }
   }
   void loop(){}
   ```
   아무것도 안 나오면 배선 또는 모듈 불량입니다

### D-2. 가만히 둬도 각도가 계속 커진다 (드리프트)

자이로 바이어스 보정이 안 된 것입니다.

- 전원을 넣는 **첫 3초 동안 배를 완전히 가만히** 두세요. 그때 보정이 일어납니다
- 흔들리는 상태에서 켜면 잘못된 바이어스가 저장됩니다. 끄고 다시 켜세요
- 평평한 곳에 놓고 켜야 합니다

### D-3. 자세값이 심하게 튄다

- MPU6050이 선체에 **단단히 고정**되어 있는지 — 양면테이프만으로는 부족합니다
- 모터 배선이 센서 바로 옆을 지나가지 않는지 — 10 cm 이상 띄우세요
- 점퍼선이 길게 늘어져 있지 않은지 — 15 cm 이내로
- 진동이 심하면 센서 아래에 **얇은 스펀지 패드**를 넣어 보세요

### D-4. 전압 표시가 실제와 다르다

분압 저항의 실측값으로 보정하면 됩니다.

1. 멀티미터로 배터리 전압을 정확히 재 둡니다 (예: 12.25 V)
2. GCS 표시값을 봅니다 (예: 11.80 V)
3. `usv_main_esp32.ino` 의 상수를 다음으로 고칩니다
   ```cpp
   const float VBAT_DIV_RATIO = 5.545f * (12.25f / 11.80f);   // = 5.756
   ```
4. 다시 업로드하고 확인

전압이 **아예 0이거나 엉뚱한 값**이면 분압 저항 배선을 확인하세요.
GPIO34에 3.3 V를 넘는 전압이 들어가면 ESP32가 손상됩니다 —
[01-HARDWARE.md 의 배터리 전압 측정 회로](01-HARDWARE.md#6-배터리-전압-측정-회로)의 저항값을 다시 확인하세요.

## E. GPS가 안 잡힌다

### E-1. 위성 수가 0이다

| 확인 | 설명 |
|---|---|
| **야외인지** | 실내에서는 거의 안 잡힙니다. 창가도 부족합니다 |
| **첫 측위 시간** | 처음 켜면 **최대 15분** 걸립니다. 콜드 스타트는 원래 느립니다 |
| 배선 | GPS TX → ESP32 **GPIO16**(RX), GPS RX → GPIO17(TX). **TX/RX는 교차**입니다 |
| 전원 | NEO-8M은 3.3 V. 모듈에 레귤레이터가 있으면 5 V도 가능 |
| 모듈 LED | 측위되면 1초 간격으로 깜빡입니다 |
| 하늘 가림 | 모듈 위에 금속·카본이 있으면 안 됩니다 |

### E-2. 위성은 잡히는데 좌표가 안 나온다

- 위성 **4개 이상**이어야 3D 측위가 됩니다. 3개 이하면 좌표가 나오지 않습니다
- GCS의 `위성` 타일이 노란색이면 아직 측위 중입니다

### E-3. 위치가 튀거나 이동궤적이 지저분하다

- 건물·나무 근처의 다중경로 반사 때문입니다. 개방된 수면에서는 훨씬 깔끔해집니다
- GPS 모듈을 선체 **가장 높은 곳**, 다른 전자부품에서 멀리 두세요
- 공유기·카메라 바로 위는 피하세요

### E-4. HDG(방위)가 이상하다

GPS 방위는 **움직일 때만 유효합니다.** 멈춰 있으면 무작위 값이 나옵니다.
0.5 m/s 이상으로 직진할 때의 값을 보세요.

## F. 영상이 안 나온다

### F-1. 공통 확인

1. 카메라 보드에 전원이 들어오는지 (LED 확인)
2. 브라우저에서 직접 열어 보세요 → `http://192.168.8.30/stream`
   - 여기서 보이면 GCS 쪽 문제
   - 여기서도 안 보이면 카메라 보드 문제
3. `http://192.168.8.30/status` 로 JSON 응답이 오는지
4. GCS의 카메라 IP 입력칸이 `192.168.8.30` 인지

### F-2. ESP32-CAM (AI-Thinker) 전용

ESP32-CAM은 까다로운 보드입니다. 거의 모든 문제가 아래 넷 중 하나입니다.

**① 전원 부족 — 가장 흔합니다**
- USB-TTL 어댑터의 5 V로는 **부족합니다.** 외부 5 V를 2 A 이상 공급하세요
- `Brownout detector was triggered` 가 반복되면 전원 문제입니다
- 5 V 핀과 GND 사이에 **470 µF 전해 커패시터**를 달면 크게 개선됩니다

**② 카메라 리본 케이블**
- `Camera probe failed (0x105)` → 리본이 덜 꽂혔습니다
- 커넥터의 검은 걸쇠를 들어 올리고, 리본을 금속면이 **보드 쪽**으로 향하게 끝까지 넣고 걸쇠를 누르세요
- 리본이 접히면 손상됩니다. 구부러진 흔적이 있으면 교체하세요

**③ GPIO0 (업로드 모드)**
- 업로드할 때만 GPIO0 ↔ GND 연결, **업로드 후 반드시 제거**하고 리셋
- 제거하지 않으면 계속 부트로더 모드에 머물러 카메라가 시작되지 않습니다

**④ PSRAM 설정**
- Arduino IDE → Tools → **PSRAM: Enabled**
- Board: **AI Thinker ESP32-CAM**
- Partition Scheme: **Huge APP (3MB No OTA)**
- PSRAM이 꺼져 있으면 VGA 이상 해상도에서 프레임 할당에 실패합니다

### F-3. XIAO ESP32S3 Sense 전용

- **확장 보드가 끝까지 끼워졌는지** — 카메라는 Sense 확장 보드에 있습니다. 반쯤 끼우면 인식되지 않습니다
- Board: **XIAO_ESP32S3**, PSRAM: **OPI PSRAM**
- 업로드가 안 되면 BOOT 버튼을 누른 채 USB를 연결 → 부트로더 모드

### F-4. 영상이 느리거나 뚝뚝 끊긴다

| 원인 | 대처 |
|---|---|
| 해상도가 높음 | GCS에서 `QVGA`(320×240)로 |
| 화질 설정이 과함 | `품질` 값을 12~15로 (숫자가 크면 화질이 낮고 가벼움) |
| Wi-Fi 신호 약함 | 거리를 줄이거나 안테나 개선 |
| 조종 명령까지 늦어짐 | **영상을 끄세요.** 조종이 우선입니다 |

### F-5. 영상이 보라색·녹색으로 깨진다

전원 부족 또는 리본 접촉 불량입니다. F-2의 ①②를 보세요.

## G. GCS 화면이 이상하다

### G-1. 그래프 영역이 하얗게 비어 있다

> 이 문제는 **v1.1.0에서 수정되었습니다.** 화면 배율(125 %, 150 % 등)에서
> 캔버스 크기가 매 프레임 불어나 결국 그려지지 않던 버그였습니다.

- 브라우저를 **강력 새로 고침**: <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>
  (옛 버전이 캐시에 남아 있을 수 있습니다)
- `gcs/index.html` 의 버전 표시가 `v1.1.1` 인지 확인
- 그래도 비어 있으면 <kbd>F12</kbd> → Console 의 오류 메시지를 확인하세요

### G-2. 데이터가 안 들어온다 / 멈춰 있다

- 상단 표시가 `신호 없음` 이면 통신 문제 → [B장](#b-wi-figcs-연결이-안-된다)
- 상태 타일이 전체적으로 흐려졌다면 2초 이상 텔레메트리가 끊긴 것입니다
- 연결은 되어 있는데 값이 안 변한다면 ESP32를 리셋해 보세요

### G-3. 엑셀 저장이 안 된다

- 먼저 `기록 시작` 을 눌러야 저장할 데이터가 생깁니다
- 브라우저의 다운로드 차단을 확인하세요
- 기록 수가 0이면 저장할 것이 없습니다

### G-4. 키보드 조종이 안 된다

- 입력칸(IP 주소 등)에 커서가 있으면 키 입력이 그쪽으로 갑니다. 화면 빈 곳을 한 번 클릭하세요
- 시동이 걸려 있는지 확인
- `조종권` 이 `RC` 로 넘어가 있지 않은지 확인

### G-5. 한글이 깨진다

파일을 UTF-8로 저장하세요. 메모장으로 편집했다면 인코딩이 바뀐 것일 수 있습니다.

## H. 펌웨어 업로드가 안 된다

### H-1. 포트가 안 보인다

- USB 케이블이 **데이터 지원** 케이블인지 (충전 전용 케이블이 많습니다)
- 드라이버 설치 — CP2102 또는 CH340. 보드에 적힌 칩을 확인하세요
- 다른 USB 포트, 다른 케이블로 바꿔 보세요

### H-2. `Failed to connect to ESP32` / `Timed out waiting for packet header`

1. 업로드가 시작될 때 **BOOT 버튼을 누른 채** 유지 → 진행률이 보이면 놓기
2. Upload Speed를 **115200**으로 낮추기
3. ESC 신호선을 **빼고** 업로드 (GPIO25·26에 걸린 부하가 방해할 수 있습니다)
4. ESP32-CAM이면 GPIO0 ↔ GND 연결 확인

### H-3. 라이브러리 오류

필요한 라이브러리는 셋입니다.

```
ESPAsyncWebServer   (me-no-dev)
AsyncTCP            (me-no-dev)
TinyGPSPlus         (Mikal Hart)
```

`ESPAsyncWebServer.h: No such file` → 라이브러리 매니저에서 설치하세요.
`AsyncTCP` 는 `ESPAsyncWebServer` 의 의존 라이브러리입니다. 둘 다 필요합니다.

### H-4. `ledcWrite` / `ledcSetup` 컴파일 오류

arduino-esp32 **코어 3.x**에서 LEDC API가 바뀌었습니다.
펌웨어에는 이미 버전 분기가 들어 있지만, 오류가 난다면 코어 버전을 확인하세요.

```
Tools → Board → Boards Manager → esp32
```

2.0.14 또는 3.x 중 하나로 통일하고, 다른 보드 패키지가 섞여 있지 않은지 확인하세요.

### H-5. 업로드는 되는데 계속 재부팅한다

시리얼 모니터(115200)의 메시지를 보세요.

| 메시지 | 원인 |
|---|---|
| `Brownout detector was triggered` | 전원 부족 → A-3, F-2① |
| `Guru Meditation Error` | 펌웨어 오류 또는 핀 충돌 |
| `rst:0x10 (RTCWDT_RTC_RESET)` | 전원 불안정 |
| `Camera init failed` | 카메라 리본 또는 PSRAM 설정 → F-2 |

## I. 물이 들어온다 / 배가 이상하다

### I-1. 선체에서 물이 샌다

| 새는 곳 | 대처 |
|---|---|
| 출력물 접합부 | **내부 필렛**이 빠졌습니다. [03-HULL.md](03-HULL.md#3-접합--키-맞춤과-에폭시) 참고 — 외부 접착만으로는 방수가 안 됩니다 |
| 해치 둘레 | 가스켓이 눌리는지 확인. 볼트를 대각선 순서로 균등하게 조이세요 |
| 케이블 관통부 | 실리콘 재충전. 케이블이 움직이면 틈이 생깁니다 |
| 샤프트 관통부 | 스터핑 박스에 그리스 재주입 |
| 출력물 벽면 자체 | 레이어 사이로 스며드는 것입니다. 내부 에폭시 코팅이 필요합니다 |

누수 지점을 찾는 방법 — 선체를 비우고 **안쪽에 휴지를 깐 뒤** 물에 띄워 10분 두세요.
젖은 휴지 위치가 누수 지점입니다.

### I-2. 배가 한쪽으로 기운다

- 배터리·장비 배치를 좌우 대칭으로
- 한쪽 선체에 물이 들어갔는지 확인 (양쪽 무게를 재 보세요)
- 좌우 선체의 출력 품질이 다르면 부력이 달라집니다

### I-3. 직진이 안 되고 한쪽으로 돈다

| 원인 | 확인 | 대처 |
|---|---|---|
| 좌우 추력 차이 | 같은 출력에서 좌우 모터 RPM | 프로펠러 피치·손상 확인 |
| 프로펠러 손상 | 날 끝 결손·변형 | 교체 |
| 무게 중심 치우침 | 좌우 무게 측정 | 장비 재배치 |
| 샤프트 정렬 불량 | 손으로 돌려 저항 비교 | 커플러 재정렬 |
| 수초 감김 | 프로펠러 육안 | 청소 |

좌우 추력이 구조적으로 다르다면 펌웨어에 좌우 보정 계수를 넣는 방법도 있지만,
**먼저 물리적 원인을 찾는 것이 정답입니다.**

### I-4. 생각보다 느리다

- 프로펠러가 너무 작습니다 → 한 치수 크게 (단, C-7의 온도 확인을 반드시)
- 선체에 물이 들어가 무거워졌는지 확인
- 배터리 잔량 — 전압이 낮으면 추력이 떨어집니다
- 출력 제한(`THR_LIMIT`)이 85 %로 걸려 있습니다. 설계값입니다

### I-5. 배가 전복됐다

1. **물에 들어가지 마세요.** 로프나 회수용 보트를 쓰세요
2. 회수 후 즉시 배터리를 분리하세요
3. 물에 젖은 LiPo는 **절대 충전하지 마세요.** 부풀거나 변색됐으면 폐기합니다
4. 전자부품은 민물로 헹군 뒤(바닷물이었다면 필수) 완전히 건조 — 최소 48시간
5. 재사용 전 모든 회로를 하나씩 점검

```
   → 예: GCS·브라우저 문제 (G장)
   → 아니오: 하드웨어·펌웨어 문제, 아래로

7. 물에 띄워도 괜찮은가?         → 아니오: I장
```
